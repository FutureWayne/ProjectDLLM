# 全流程 UI 重做 TODO

本清单覆盖从启动游戏到退出对局的玩家可见界面。这里的“重做 Lyra UI”指替换 Lyra 默认视觉、文案与模板式交互，并统一项目自己的 CommonUI / CommonGame 导航和状态流；不要求删除仍承担输入、焦点、弹层、设置存储或会话功能的底层框架。

## 优先级与难度

- **P0 上线阻塞**：没有它会阻止玩家进入、完成或退出一局，或暴露明显占位内容。
- **P1 首发体验**：首发应完成；可先交付精简版，重点是信息清晰和操作可靠。
- **P2 完整度**：可在首发后迭代，不阻止核心流程上线。
- **难度 S / M / L / XL**：相对工作量。XL 通常涉及多个状态、网络数据、导航或跨系统联调，不仅是画面制作。

## 仓库现状与执行注意

- 项目已有 Arena 风格组件，不应全部推倒重做：`WBP_ArenaTopBar`、部分 HUD、命中反馈、生命条、击杀 feed、重生提示和比分板都已有资产或实现。先判断可复用/需统一样式/需替换，再逐页处理。
- 配置明确仍使用 `W_LyraLogo_LoadingScreen`；菜单目录仍有 `W_LyraMenuButton`、`W_LyraArrowButton` 等 Lyra 命名资产。它们是否仍被运行时引用需在编辑器中确认，不能只凭文件存在判断活跃状态。
- 菜单和大厅存在多套可能重叠的资产路径（例如 `UI/Menu/Lobby` 与 `UI/Scoreboard/W_LobbyPlayerList`）。第一步在 Unreal Editor 中从 Widget Blueprint、UI Policy、Experience 和地图引用追踪实际运行路径，再删除或归档未使用资产。
- 重做 UI 不等于重写网络/设置后端。会话、登录、玩家列表、得分、重生和设置应消费现有状态；缺少的数据能力单独登记为系统 TODO，避免把纯 UI 工期估低。

## 建议执行顺序

1. **先追踪真实入口并冻结首发页面**：完成 UI-01 到 UI-11 的引用核验，标记实际使用的 Widget、导航方式和数据来源。
2. **先搭公共基础**：UI-31 到 UI-33 定稿，再并行做前端和 HUD，避免重复返工。
3. **优先打通多人入局和错误路径**：UI-05 到 UI-11 连续实测，然后完成 UI-12 到 UI-18 的对局闭环。
4. **完成首发设置和本地化**：UI-19 到 UI-23；文本和字体应尽早介入，不等页面全部完工。
5. **按首发玩法补专属 UI**：占点/强化掉落只有确认纳入首发后才执行 UI-24。
6. **发布前集中验收**：UI-34、UI-35，并检查 UI-33 的 Lyra 品牌与模板残留。
